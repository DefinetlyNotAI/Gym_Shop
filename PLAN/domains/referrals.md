# Referrals and reward qualification

Owns referral codes, attribution and reward qualification. [Identity](identity-access.md) owns verification; [Pricing](pricing.md) owns buyer discounts; [Wallet](wallet-loyalty.md) owns money and payouts.

## Requirements

- **REF-01 — Codes:** Every registered account gets a random code and shareable /?ref=CODE link; manual checkout entry also supported. Normal users cannot customize. Approved verified customers may choose a unique case-insensitive code subject to configurable length/characters/reserved words; optional retention of old codes. Each code has one owner; authorized staff can disable it. Record exact used code historically.
- **REF-02 — Attribution/code UX:** Link prepopulates a visible removable checkout referral code. Different code entry while one is present returns an error instructing removal first; never silently replace. Before order confirmation allow remove then replace; after qualifying-order lock preserve attribution. One referrer/customer, no self-referral or referral after completed order. Proposed link retention thirty days; atomic account-level first-order lock prevents concurrent rewarded first orders. Historical codes remain unchanged by later renaming.
- **REF-03 — Reward:** Referrer earns 2% of discounted merchandise after discounts and before fees; [Defaults](../04-defaults.md) defines the calculation excluding shipping/tax/redelivery fees; wallet tender does not reduce the reward base. Buyer benefit uses shared pricing; chosen launch default 5% first-order merchandise with configured limits. Pending bonus becomes available at successful delivery/verified pickup plus authoritative payment/customer cash collection, not mere order placement. Finance's driver remittance remains separate and does not punish an honest customer's reward. Preserve ATTRIBUTED, PENDING, QUALIFIED, COMPLETED, REJECTED, REVOKED history. Failed/cancelled orders do not earn; refunds/fraud reverse by ledger reference. All available wallet sources follow current verification withdrawal eligibility under WAL-04.
- **REF-04 — Administration and customer view:** Show code/link, optional clicks, signups, pending/completed/rejected counts, earnings/history; wallet supplies available/pending/spent/lifetime amounts. Admin search accounts, relationships/orders, pending/completed/suspicious rewards; configure campaigns/rates, disable codes, invalidate referrals and request wallet freezes/revocations with reasons and actors. Rate-limit attribution and flag suspicious relationships; IP alone is not proof. Finance handles payouts. Do not disclose referred people's unnecessary identity/purchase details.

## Acceptance

Existing registered accounts also receive a unique random code when referrals launch; backfill is idempotent and never replaces an assigned code. Code uniqueness is case-insensitive; nonverified customization fails. Customer cannot self-refer or switch referrer after attribution locks. Payment/reward event replay credits only once at the accepted milestone. Failed/cancelled orders do not leave unqualified rewards available. Freeze/revoke preserves history; already-spent reward recovery goes to manual review rather than silently creating debt.
